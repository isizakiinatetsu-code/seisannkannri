# 納入管理システム 導入効果レポート

作成日: 2026-06-19
対象: 鋼材・建材 納入管理システム（Next.js + Supabase / クラウド運用）

---

## 1. 背景 ― 現状の課題

本システム導入前は、納入（納品）に関する情報共有が次のような運用になっていました。

### 課題① 納品書を「写真」で管理・共有している
- スマホで撮った納品書の写真を、その都度メールやチャット、あるいは個人の端末でやり取りしていた。
- 写真がどの物件・どの発注に対応するのか、**ファイル単体では判別しづらい**。
- 撮影者の手元や特定のフォルダに散在し、**必要な納品書を後から探し出すのに時間がかかる**。
- 写真は斜め・暗い・反射などで**読みにくく**、保管・転送中に**紛失・上書き**のリスクがある。

### 課題② 生産管理が現場からの問い合わせに「電話」で対応している
- 「あの材料はいつ入る？」「もう納入された？」「業者はどこ？」といった問い合わせが、
  その都度**生産管理に電話で集中**していた。
- 生産管理が手を止めて口頭で回答するため、**本来業務が中断**される。
- 電話は**1対1・記録に残らない**ため、同じ問い合わせが繰り返され、伝え間違いも起こりうる。
- 現場は生産管理が電話に出られないと**確認が止まる**（時間外・外出中は特に）。

---

## 2. 本システムで解消が見込めること

### 課題① 納品書の写真管理・共有 → 「予定に紐づくクラウド台帳」へ

| 解消される点 | 仕組み |
| --- | --- |
| 写真が散在し探せない | 納品書画像を**該当の納入予定（物件・品目・発注番号）に直接ひも付けて**保存。1件の予定に複数枚の伝票を添付可能。 |
| 端末依存・紛失リスク | 画像を**クラウド（Supabase Storage）に集約**。さらに **Google Drive の【納入管理】フォルダへ自動二重保存**するため、片方が失われても残る。 |
| どの納入か分からない | 検索（物件名・業者・品目・降し場所・日付・ステータス）で**該当する伝票へ即到達**できる。 |
| 写真が読みにくい | 撮影画像を**スキャン書類風に自動補正**（後述の工夫を参照）。 |
| 書類としてまとめづらい | 複数の伝票を**1つのPDFに綴じて出力**（ファイル名に物件名・日付が自動付与）。 |

→ 「写真をやり取りする運用」から、**誰が見ても同じ最新の納品書台帳をクラウドで共有する運用**へ移行できます。

### 課題② 電話での問い合わせ対応 → 「現場が自分で見て分かる」セルフ確認へ

| 解消される点 | 仕組み |
| --- | --- |
| 問い合わせが生産管理に集中・本来業務が中断 | 納入予定・ステータス（予定／納入済み）・納品書を**現場が自分で画面で確認**できるため、電話そのものが減る。 |
| 「いつ入る／入ったか」の確認 | カレンダー／リストで**納入予定日・時間帯（午前中・午後・時刻指定）と進捗（X/Y件 納入済み）**を一覧表示。 |
| 「どの業者・どこへ降ろす」の確認 | 業者名・降し場所（第1工場 など）・納入場所・数量・発注番号まで**1画面で参照**。 |
| 外出中・時間外で電話がつながらない | **インターネット越しにクラウドアクセス**。現場・外出先からスマホで確認できる。 |
| 口頭で記録が残らない | 情報が**台帳としてデータ化**され、誰が見ても同じ内容。状態変更も日時付きで残る。 |

→ 「電話で聞く」運用から、**現場がスマホで自分で確認し、生産管理は登録・更新に専念する**運用へ移行できます。

## 3. 注目すべき「工夫」

単なるデータ登録にとどまらない、現場運用を意識した工夫が実装されています。

1. **納品書のスキャン風自動補正（OpenCV.js）**
   現場でスマホ撮影した伝票の四隅を自動検出し、台形補正（パース補正）＋白黒二値化で
   **コピー機でスキャンしたような読みやすい書類**に変換。失敗時もグレースケール処理にフォールバック。
   → 「とりあえず撮るだけ」で、保管・転送に耐える品質になります。

2. **クラウド＋Google Drive の二重保存（ベストエフォート）**
   伝票はクラウドに保存しつつ Google Drive にも自動アップロード。Drive 側が失敗しても
   本体の保存は成功扱いとし、**運用を止めない**設計。普段使い慣れた Drive 上でも閲覧できます。

3. **複数伝票のPDF一括出力（jsPDF）**
   1物件に複数枚ある伝票を**1つのPDFにまとめて**出力。ファイル名は「納入伝票_物件名_日付.pdf」と
   自動命名され、そのまま社内提出・保管に使えます。

4. **マルチデバイス対応UI（PC／iPad／スマホ）**
   PCは左サイドバー、iPadは上部タブ、スマホはボトムナビ＋スワイプ操作と、
   **端末ごとに最適化**。現場での片手操作を想定。

5. **品目カテゴリの色分け**
   型板＝赤、鋼材＝緑、ボルト＝紫…とカレンダー・リストで**色で一目判別**。

6. **編集／閲覧の権限分離**
   パスワードで「編集」と「閲覧」の2ロールに分岐。現場の多くは**閲覧専用で安全に共有**しつつ、
   登録・更新は限られた人だけが行える。操作系API（追加・変更・削除）はサーバ側でも権限チェック。

7. **Google Sheets からの取り込み連携**
   既存の Google Sheets の予定を取り込み（重複排除・日付正規化・過去3ヶ月フィルタ）、
   **既存の入力運用からの移行**をしやすくしている。

8. **状態管理と進捗の可視化**
   「予定 → 納入済み」を日時付きで記録（取り消しも可能）。リストでは日別の納入進捗率を表示し、
   **当日の入荷状況がひと目で**分かる。

## 4. まとめ ― 期待される効果

- **納品書**: 写真の散在・紛失・判別困難 → **予定にひも付いたクラウド台帳で一元管理・即検索・二重バックアップ**。
- **問い合わせ対応**: 電話の集中・業務中断・記録なし → **現場がスマホでセルフ確認、生産管理は本来業務に集中**。
- **副次効果**: 伝言ミスの削減、時間外・現場からの確認可能化、書類化（PDF）による保管・提出の効率化。

定量的には「**生産管理への電話問い合わせ件数の削減**」「**納品書を探す時間の短縮**」を
導入後のKPIとして測定することを推奨します。

---

## 5. 補足 ― 今後さらに効果を高めるための実装余地

現状は計画段階で、効果をさらに伸ばす余地として以下があります。

- **操作者の記録**（誰が登録・更新したか / `created_by`・`updated_by`、監査ログ）… 「誰が対応したか」の追跡。
- **リアルタイム反映・通知**（入荷時に現場へ自動通知）… 確認のための「見に行く」操作自体を不要に。
- **OCRによる伝票の自動読み取り**（現状は画像保存のみ、OCRタブは名称のみ）… 入力工数の削減。
- **Supabase 認証・RLS の本格導入**… セキュリティと個人単位の権限の強化。
